# pre-code

코딩을 시작하기 전에 요구사항을 명확히 정리합니다.
사용자의 자연어 요청을 받아 빠진 정보를 질문하고, 확인된 내용을 구조화된 요구사항으로 요약합니다.

## RefPMS 도메인 지식 (사전 참조)

3계층 구조: `Project → Class → Component`
주요 UI 진입점:
- 메인 창 → Generate PMS
- Class Template Wizard → Class_Define / Schedule / Components / Reducing / Branch 탭
- Project Settings Dialog

## 절차

### Step 1 — 요청 파악
사용자가 입력한 요청을 읽고 아래 항목 중 불분명한 것을 파악합니다.

체크 항목:
- **대상**: 어떤 탭 / 다이얼로그 / 기능인가?
- **계층**: Project / Class / Component 중 어느 레벨인가?
- **변경 종류**: 추가 / 수정 / 삭제 중 무엇인가?
- **기존 동작 유지**: 현재 동작하는 것들이 그대로여야 하는가?
- **트리거 조건**: 어떤 상황에서 동작해야 하는가?
- **예외/엣지케이스**: 빈 값, 잘못된 값, 경계값 처리 필요한가?

### Step 2 — 질문
불분명한 항목에 대해 **한 번에 최대 3개**까지만 질문합니다.
이미 명확한 항목은 질문하지 않습니다.
모든 항목이 명확하면 질문 없이 Step 3으로 바로 넘어갑니다.

### Step 3 — 요구사항 정리
사용자 답변을 반영해 아래 형식으로 정리하고 확인을 요청합니다.

```
## 요구사항 정리

**목표**: (한 줄 요약)

**대상**: (탭/다이얼로그/함수)
**변경 종류**: 추가 / 수정 / 삭제
**기존 동작 유지**: 예 / 아니오

**동작 명세**:
1. (조건) → (결과)
2. ...

**예외 처리**:
- ...

---
이대로 진행할까요?
```

사용자가 확인하면 Claude가 바로 구현에 들어갑니다.
