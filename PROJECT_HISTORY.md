# Project RefPMS: Engineering History & Architecture Log

## 1. The Core Architecture: "Universal PMS Data Engine"
Instead of a simple converter, the project is being redesigned as a **Universal Data Engine**. The central philosophy is to separate **Intent (Input)** from **Representation (Output)** by using a highly structured, hierarchical Schema. 

The goal is to build a robust database-like structure that stores piping material data in its most granular, "Atomic" form. Once this structure is populated, any specific file format can be generated by simply mapping these attributes.

## 2. The 5-Layer Hierarchical Schema
We have defined a 5-layer system to manage the complexity of piping engineering data. Every individual component is "assembled" by inheriting attributes from these layers:

### Layer 1: The Project (Global Context)
*   **Role:** Defines the project-wide "Laws of Physics."
*   **Key Attributes:** Unit System (Inch/Metric), NPS Master List (valid sizes), Global Coding Rules (Commodity Code templates), and Project Metadata.

### Layer 2: The Class / Spec (Technical Envelope)
*   **Role:** Defines the engineering constraints for a specific piping class.
*   **Key Attributes:** Design Code (e.g., ASME B31.3), P/T Rating (e.g., 150#), Service Context (Fluid, Corrosion Allowance), and **Thickness Lookup Tables** (Schedule/Rating per NPS).

### Layer 3: Group Layer (Functional Logic)
*   **Role:** Categorizes components and defines functional requirements.
*   **Key Attributes:** Categories (Pipe, Fitting, Flange, Valve). Defines which technical fields are required for each category (e.g., Valves require "Operation Type," while Pipes require "Manufacturing Method").

### Layer 4: Definition Layer (The Engineering "DNA")
*   **Role:** Stores the core technical rules for a range of sizes.
*   **Key Attributes:** Material Standard (e.g., ASTM A106), Grade (e.g., Gr.B), Method (SMLS/ERW), End Types (BW, SW, PE, TE), and Geometry (Angle, Facings). 
*   **Status:** This is the current focus—defining a schema that covers all component types.

### Layer 5: Atomic Layer (Discrete Data Points)
*   **Role:** The most granular level—the final result of the engine's processing.
*   **Logic:** A single object representing one specific size (e.g., a 2" Sch 80 Pipe) that has inherited and calculated all its properties from Layers 1-4.

## 3. The Logic Bridge: Component Assembly
We brainstormed the assembly of a single item (e.g., a 2" Elbow) to test the schema:
*   **Project Layer** provides the unit (inch) and validates the size (2").
*   **Class Layer** looks up the specific thickness (Sch 80) from its table.
*   **Group Layer** identifies it as a "Fitting," triggering the need for an "Angle."
*   **Definition Layer** provides the DNA: 90 DEG, A234-WPB, SMLS, BW, B16.9.
*   **Atomic Layer** merges these into one rich data record.

## 4. Technical Constraints
*   **Internal Size Explosion:** The engine must internally expand all ranges (e.g., 0.5-2) into Layer 5 Atomic records to ensure every size is technically validated against Layer 2 Thickness Tables.
*   **Attribute Independence:** Data is stored as individual "Atomic Attributes" (Material, Grade, Schedule) rather than pre-formatted strings, allowing for infinite flexibility in how data is exported later.
